# NemoClaw

Ops repo for per-user NVIDIA NemoClaw deploys. Not an upstream fork. PoC target is `personal_config/poc` (`poc-claw`, Hermes, Ollama `qwen3:4b`). Actions for `poc` run on `runs-on: [self-hosted, macOS, ARM64, chalmers-macmini-node-1]`.

## GOTCHA

- Actions checkout deletes gitignored files under `actions-runner/_work`. The first Actions run copies `personal_config/secrets.env.example` to `~/.nemoclaw/runner-secrets/<target>/secrets.env` mode 600 and stops. Fill that file on the runner and rerun. Later runs do not overwrite it.
- Compose project names must be lowercase. `NemoClaw-poc` is rejected. Use project `nemoclaw-<user>`; container, network, and volume names can stay `NemoClaw-<user>-*`.
- Homebrew OpenShell on a new Mac is `brew tap nvidia/openshell`, `brew trust nvidia/openshell`, then `brew install nvidia/openshell/openshell`. `brew services start openshell` fails while the formula is missing, and an untrusted tap refuses the install. The port owner is `docker-proxy`, `socat`, or `com.docker.backend`, including when the controller shares the gateway pid and netns. Homebrew `openshell-gateway` `0.0.116` on `127.0.0.1:8080` is the path onboard accepts. The compose gateway image (`0.1.4`) stays unused on this Mac, and the controller service stays stopped.
- OpenShell image tags omit `v` (`ghcr.io/nvidia/openshell/gateway:0.1.4`). The CLI tarball uses `v0.1.4`. Gateway `0.0.116` rejects a newer `gateway.toml` field such as `compute_driver`.
- Hermes onboard requires loaded context ≥ 64000. `qwen2.5:3b` is 32k and is rejected. `qwen3:4b` qualifies. Exact 3B means `NEMOCLAW_AGENT=openclaw` and `NEMOCLAW_MODEL=qwen2.5:3b`.
- `qwen3:4b` with a 64k fp16 KV cache is SIGKILL'd inside Docker Desktop's ~7.7 GiB VM. Set `OLLAMA_FLASH_ATTENTION=1`, `OLLAMA_KV_CACHE_TYPE=q4_0`, `OLLAMA_MAX_LOADED_MODELS=1`, `OLLAMA_NUM_PARALLEL=1`. Set `NEMOCLAW_IGNORE_RUNTIME_RESOURCES=1` because the VM reports under 8 GiB.
- Compose Ollama and the macOS host Ollama both bind `:11434`. On macOS stop the compose container and keep LaunchAgent `com.nemoclaw.ollama`; the Linux VM cannot use the M4 GPU. `free_compose_ports` skips `:11434` in that case and must not kill `Docker.app` or `com.docker.backend`. Linux targets still run Ollama in compose. `q4_0` KV stays on, because a 64k fp16 cache for `qwen3:4b` is about 10 GiB before weights and does not fit comfortably in 16 GB.
- Gateway `GET /` is 404. Treat 2xx–4xx as up. `curl -f` marks a live gateway down.
- macOS bash 3.2 has no nameref. A `curl | bash` installer only sees `NEMOCLAW_*` when they are exported on the bash side of the pipe.
- Docker Desktop `extra_hosts` maps `host.openshell.internal` to `192.168.65.254` and `fdc4:f303:9324::254`. The L7 proxy prefers the IPv6 ULA. `allowed_ips` is only `10/8`, `172.16/12`, and `192.168/16`, so the result is `ssrf_denied` and HTTP 503. Strip IPv6 `host.openshell.internal` lines from the sandbox `/etc/hosts`, and append a real `precedence ::ffff:0:0/96  100` to `/etc/gai.conf`. The stock file only has that line inside a comment, so match a marker such as `# nemoclaw-prefer-ipv4`.
- A native macOS gateway resolves `host.openshell.internal` on the Mac, not from the sandbox hosts file. Add `10.255.255.254` on `lo0` and the same line in `/etc/hosts`. `sudo -n` fails until the user has a cached sudo credential.
- Do not add a second `host.openshell.internal:11435` policy endpoint. It overlaps the provider CIDRs. `policy set` of a full document fails on the reserved `_provider_` prefix. `--add-endpoint` cannot take an IPv6 `allowed-ip` because `::` breaks the option grammar.
- `openshell inference set` accepts only `openai`, `anthropic`, `nvidia`, `deepinfra`, `google-vertex-ai`, and `aws-bedrock`. The attached type `nemoclaw-local-authenticated-v1-…` is rejected with "unsupported type for cluster inference". Without an openai-type route, `https://inference.local` returns 503 `cluster inference is not configured` or `inference service unavailable`.
- `nemohermes <sandbox> status` omits `agentName` unless the agent is `langchain-deepagents-code`. For Hermes that probe posts to `https://inference.local/v1/chat/completions` and reports HTTP 503 even when `http://host.openshell.internal:11435/v1/chat/completions` returns 200. The local CLI under `~/.nemoclaw/source` needs `agentName: sb.agent` in both `src/lib/actions/sandbox/status-snapshot.ts` and the matching `dist` file. Three retries about 2 seconds apart are that 503, not a slow generate.
- Hermes `config.yaml` can store a frozen `openshell:resolve:env:v<rev>_NEMOCLAW_LOCAL_INFERENCE_TOKEN`. After the revision changes, Discord fails with HTTP 500 `credential_injection_failed` / `unresolved credential placeholder`. Write `${NEMOCLAW_LOCAL_INFERENCE_TOKEN}` into `model.api_key`, `providers.ollama-local.api_key`, and the matching `custom_providers` entry, then `nemohermes <sandbox> gateway restart`. `recover` will not restart a gateway it already considers healthy.
- A failed onboard can leave `platforms.discord.enabled: false` while `DISCORD_BOT_TOKEN` is already in the sandbox env. Hermes then logs that it will not start the adapter. Set `platforms.discord.enabled` and `discord.require_mention`, then gateway-restart. `require_mention` means the bot ignores messages that do not mention it. `/sethome` is optional and is not the inference failure.
- `openshell sandbox exec poc-claw -- …` treats `poc-claw` as the remote command. Use `openshell sandbox exec -n poc-claw --no-tty -- …`.
- Hermes on this CPU sends about 10k tokens of tool preamble before a Discord reply. `qwen3:4b` prompt eval is roughly 30–50 tokens/s, so the first reply takes minutes. A 60s client timeout is not proof the route is down. A direct 16-token curl to `:11435` returns in about a second.
- A Discord session invalidation does not replay mentions sent in that gap. `gateway.log` can show `Connected as chalmers-assistant-poc` and then no `inbound message`. Those pings are gone; mention the bot again after the Connected line.
- Sandbox user cannot `pip install` into `/opt/hermes/.venv` (`Permission denied`). A water reminder does not need that package. Hermes cron job `hydrate` (`951e113601ce`) runs `scripts/hydrate_ping.py` with `no_agent` and delivers stdout to Discord. Schedule `25-59/5 * * * *` is minute 25, 30, 35, 40, 45, 50, 55. Delivery lands in `#home` and does not notify unless the text contains a user mention.
- The PoC role `chalmers-assistant-poc` (`<@&1560925507900407818>`) is not the bot user. Hermes ignores that role ping when `require_mention` is on, with no log and no 👀. `discord.free_response_channels` is `"*"` so every text channel in guild `chalmers-poc` is answered without a user mention. `#home` (`1560990673958735943`) is `platforms.discord.home_channel` and `DISCORD_HOME_CHANNEL`. A `qwen3.5:9b` Discord turn with the tool preamble took about two minutes and then posted.
- macOS Ollama deploy does not call `free_compose_ports` and does not start the compose gateway or compose Ollama. It starts Homebrew `openshell`, host Ollama, and the `:11435` auth proxy, then runs host `onboard --resume` only. Resume failure does not fall through to a fresh onboard. `upgrade` runs `upgrade-sandboxes` only and does not delete `nemoclaw-hermes-state-v1-poc-claw`.
- `OLLAMA_KEEP_ALIVE` in the LaunchAgent plist is `5m`. Idle time unloads the weights. The next Discord reply pays the load again. Parallelism stays 1 and KV stays `q4_0`.
- Auth proxy LaunchAgent `com.nemoclaw.ollama-auth-proxy` runs `scripts/ollama-auth-proxy-agent.sh`. The token stays in `~/.nemoclaw/ollama-proxy-token` and is not written into the plist. The `lo0` alias LaunchDaemon is installed only when `sudo -n` works.
- `status.sh` must not require the compose `nemoclaw` service on this Mac. The working check is the host `nemohermes` binary.
- `ensure-local-llm.sh` boots out `com.nemoclaw.ollama` and then `launchctl bootstrap` can fail with `Bootstrap failed: 5: Input/output error`, which leaves the daemon down. Retry `launchctl bootstrap gui/$UID ~/Library/LaunchAgents/com.nemoclaw.ollama.plist` once the previous job has exited.
- Do not `kill -9` the Hermes gateway pid inside the sandbox. The container exits 137 and OpenShell 0.0.116 stays in phase `Error`. `openshell sandbox stop` and `start` both refuse that phase, and `docker start` brings the process back while the phase stays `Error`. Recovery: `docker stop` the sandbox container, `launchctl bootout` `sh.brew.openshell`, and in `~/.local/state/nemoclaw/openshell-docker-gateway/openshell.db` change the single status byte after `Canonical main process exited` from `0x03` (Error) to `0x07` (Stopped). Bootstrap the gateway, then `openshell sandbox start`. Phase returns `Ready`. A container restart rewrites `/etc/hosts` with the IPv6 `host.openshell.internal` line and inference is `ssrf_denied` until `repair_sandbox_openshell_hosts` removes it. That repair's `docker exec` must pass `-i`, or the Python never runs and the IPv6 line stays.

## TASTE

- PoC config: `OS=macos`, `NEMOCLAW_AGENT=hermes`, `NEMOCLAW_PROVIDER=ollama`, `NEMOCLAW_MODEL=qwen3:4b`, `NEMOCLAW_SANDBOX_NAME=poc-claw`, `NEMOCLAW_YES=1`, `NEMOCLAW_IGNORE_RUNTIME_RESOURCES=1`. Discord guild id stays in `config.env`. The bot token stays in `personal_config/poc/secrets.env` mode 600. `qwen3.5:9b` at 64k with `q4_0` KV was 7.2 GiB and 100% GPU on 16 GB, so it is not the default. `qwen3:8b` waits on a context and RSS measurement. `ensure_openshell_openai_inference` updates the model on an existing openai route and does not recreate the provider. Hermes `api_key` stays `${NEMOCLAW_LOCAL_INFERENCE_TOKEN}`. Body rewrite is enabled on the existing `:11435` endpoint only after a rewrite denial. Do not set `allow_uninspected_credentials`.
- Working Mac processes: Homebrew `openshell-gateway` `0.0.116` on `127.0.0.1:8080`, host Ollama LaunchAgent `com.nemoclaw.ollama` on `127.0.0.1:11434` (Metal), NemoClaw auth proxy on `:11435`, sandbox `openshell-default--poc-claw-*`. Pins: NemoClaw `1e82499a048d5a4d85b0876d8c07bd93c8a9a5de`, Hermes Agent `0.21.3`, CLI `0.1.0` linked from `~/.nemoclaw/source`. Start or refresh that daemon with `bash ./scripts/ensure-local-llm.sh poc`.
- Authenticated sandbox chat that returns 200: L7 proxy `10.200.0.1:3128` to IPv4 `host.openshell.internal:11435` with `Authorization: Bearer $NEMOCLAW_LOCAL_INFERENCE_TOKEN`. The token value in the sandbox is an `openshell:resolve:env:…` handle, not the raw proxy token. OpenShell rewrites it.
- Cluster route that makes `inference.local` eligible: create an `openai` provider whose base URL is `http://127.0.0.1:11435/v1` and whose key is the contents of `~/.nemoclaw/ollama-proxy-token`, then `openshell inference set` for both the user route and `--system`, then `openshell sandbox provider attach`. Reuse an existing provider name if one is already there. `scripts/common.sh` does this in `ensure_openshell_openai_inference`.
- Before status or connect, `repair_sandbox_openshell_hosts` strips sandbox IPv6 `host.openshell.internal` lines and writes the gai.conf marker. `ensure_hermes_discord_platform` flips a disabled Discord platform and recovers the gateway.
- Green check on this Mac, from the host CLI: `nemohermes poc-claw status` shows Inference healthy at `http://host.openshell.internal:11435/v1/chat/completions`, and `nemohermes poc-claw connect --probe-only` ends `result=ready`. Discord bot name on this PoC is `chalmers-assistant-poc`.
- The original M4 laptop PoC was stopped with `openshell sandbox stop poc-claw`, `brew services stop openshell`, and `launchctl disable` for `sh.brew.openshell` and `com.nemoclaw.ollama`. The `:11435` auth proxy was killed. Those two LaunchAgents stay disabled across login. `poc` deploy and status now use `runs-on: [self-hosted, macOS, ARM64, chalmers-macmini-node-1]`; `chalmers` and `cliff` stay on `nemoclaw,<user>`. The Mac mini runner's extra label is `chalmers-macmini-node-1`.
